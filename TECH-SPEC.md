## 1. Stack and Dependencies

### Python Version

Python **3.12** (minimum 3.12.0). The GitHub Actions runner uses `python-version: "3.12"`.

### Pinned Dependencies (`requirements.txt`)

```
anthropic==0.49.0
openai==1.75.0
requests==2.32.3
python-dotenv==1.1.0
pyyaml==6.0.2
```

**Rationale for non-obvious pins:**

- `anthropic==0.49.0` — Pins to the version that exposes `web_search_result` content blocks in the response, which is required for citation extraction. Any bump must be manually validated against citation parsing.
- `openai==1.75.0` — Pins to the version where `response.output` contains `web_search_call` and `message` items in the Responses API format. The Responses API (`client.responses.create`) is used, not Chat Completions, because it exposes structured tool call outputs with URLs.
- `requests==2.32.3` — Used for Perplexity only (Sonar API is a plain REST endpoint with no official SDK). `httpx` is explicitly not used to keep the dependency surface minimal.
- `pyyaml==6.0.2` — Safe-load only. Never `yaml.load()` anywhere in the codebase; always `yaml.safe_load()`.

### Dev Dependencies (`requirements-dev.txt`)

```
pytest==8.3.5
pytest-cov==6.1.0
responses==0.25.3
ruff==0.11.6
```

- `responses` is the HTTP mock library for testing Perplexity calls without hitting the network.
- `ruff` handles both linting and formatting. No separate `black` or `flake8`.

## 3. SQLite Schema

The canonical schema lives in `/src/schema.sql`. `db.py` applies it via `executescript` on every connection using `CREATE TABLE IF NOT EXISTS`. No migrations framework is used; schema changes are append-only (add columns with defaults, never drop). Breaking changes require a new table name and a note in `decisions-log.md`.

### Table: `queries`

Stores the static definition of each research query. Populated from `prompts.yaml` at the start of each run. Rows are inserted with `INSERT OR IGNORE` so re-runs do not duplicate.

```sql
CREATE TABLE IF NOT EXISTS queries (
    query_id        TEXT PRIMARY KEY,           -- Slug from prompts.yaml, e.g. "brand-visibility-q1"
    topic           TEXT NOT NULL,              -- Human-readable topic label
    prompt_text     TEXT NOT NULL,              -- Exact prompt string sent to engines
    is_variant      INTEGER NOT NULL DEFAULT 0, -- 1 if this is a stability sub-study variant
    variant_of      TEXT,                       -- query_id of the canonical prompt this varies from; NULL if is_variant=0
    created_at      TEXT NOT NULL               -- ISO-8601 UTC timestamp when first inserted
);
```

### Table: `runs`

One row per (query, engine, repetition). Three rows per query per engine per month minimum.

```sql
CREATE TABLE IF NOT EXISTS runs (
    run_id          TEXT PRIMARY KEY,           -- UUID4, generated in Python
    query_id        TEXT NOT NULL REFERENCES queries(query_id),
    engine          TEXT NOT NULL,              -- "chatgpt" | "perplexity" | "claude"
    model_version   TEXT NOT NULL,              -- Exact model string returned by API, e.g. "gpt-4o-2024-11-20"
    run_number      INTEGER NOT NULL,           -- 1, 2, or 3 within the monthly batch for this query+engine
    month           TEXT NOT NULL,              -- "YYYY-MM", the reporting month this run belongs to
    prompt_sent     TEXT NOT NULL,              -- Verbatim prompt string actually sent
    response_text   TEXT NOT NULL,              -- Full plain-text answer returned by engine
    input_tokens    INTEGER NOT NULL,
    output_tokens   INTEGER NOT NULL,
    cost_usd        REAL NOT NULL,              -- Calculated cost in USD for this single run
    ran_at          TEXT NOT NULL,              -- ISO-8601 UTC timestamp of API call completion
    error           TEXT,                       -- NULL on success; error message string on failure
    UNIQUE(query_id, engine, run_number, month)
);
```

### Table: `citations`

One row per URL cited per run. A single run may produce zero or many citations.

```sql
CREATE TABLE IF NOT EXISTS citations (
    citation_id     TEXT PRIMARY KEY,           -- UUID4, generated in Python
    run_id          TEXT NOT NULL REFERENCES runs(run_id),
    url             TEXT NOT NULL,              -- Full URL as returned by engine
    title           TEXT,                       -- Page title if engine provides it; NULL otherwise
    position        INTEGER NOT NULL,           -- 1-based order in which the citation appeared
    domain          TEXT NOT NULL,              -- Extracted eTLD+1, e.g. "nytimes.com" (computed in Python)
    cited_at        TEXT NOT NULL               -- ISO-8601 UTC timestamp; copied from parent run's ran_at
);
```

### Table: `costs`

One row per run per month. Denormalized from `runs` intentionally so the budget check is a single fast aggregate query without joining.

```sql
CREATE TABLE IF NOT EXISTS costs (
    cost_id         TEXT PRIMARY KEY,           -- UUID4
    run_id          TEXT NOT NULL REFERENCES runs(run_id),
    engine          TEXT NOT NULL,              -- "chatgpt" | "perplexity" | "claude"
    month           TEXT NOT NULL,              -- "YYYY-MM"
    cost_usd        REAL NOT NULL,
    recorded_at     TEXT NOT NULL               -- ISO-8601 UTC timestamp
);
```

**Budget query used by circuit breaker:**

```sql
SELECT COALESCE(SUM(cost_usd), 0.0) FROM costs WHERE month = ?;
```

## 4. Normalization Schema

All three engine integrations must return a `NormalizedResult` dataclass (defined in `/src/models.py`) before any data is written to SQLite. No engine-specific data structure may be passed to `db.py`.

### `NormalizedResult` Fields

| Field | Python Type | Description |
|---|---|---|
| `run_id` | `str` | UUID4, generated by the engine before the API call |
| `query_id` | `str` | Slug from `prompts.yaml` |
| `engine` | `str` | Literal `"chatgpt"`, `"perplexity"`, or `"claude"` |
| `model_version` | `str` | Exact model string returned in the API response |
| `run_number` | `int` | 1, 2, or 3 |
| `month` | `str` | `"YYYY-MM"` |
| `prompt_sent` | `str` | Verbatim prompt string actually sent |
| `response_text` | `str` | Plain text of the answer, stripped of any markup |
| `input_tokens` | `int` | As reported by the API |
| `output_tokens` | `int` | As reported by the API |
| `cost_usd` | `float` | Computed by the engine class using pricing constants |
| `ran_at` | `str` | ISO-8601 UTC timestamp |
| `citations` | `list[Citation]` | Empty list if no citations; never `None` |
| `error` | `str \| None` | `None` on success; populated on partial failures only |

### `Citation` Fields

| Field | Python Type | Description |
|---|---|---|
| `citation_id` | `str` | UUID4, generated during parsing |
| `url` | `str` | Full URL as returned by engine |
| `title` | `str \| None` | Page title if available; `None` otherwise |
| `position` | `int` | 1-based order in response |
| `domain` | `str` | eTLD+1 extracted via `urllib.parse` + last-two-segments split |

### Per-Engine Mapping to NormalizedResult

**ChatGPT (OpenAI Responses API)**
- `model_version` — from `response.model`
- `response_text` — from the `output_text` of the `message` item in `response.output`
- `input_tokens` — from `response.usage.input_tokens`
- `output_tokens` — from `response.usage.output_tokens`
- `citations` — from `web_search_call` items in `response.output`; each result in `output[n].results` has `url` and `title`

**Perplexity (Sonar REST API)**
- `model_version` — from `response_json["model"]`
- `response_text` — from `response_json["choices"][0]["message"]["content"]`
- `input_tokens` — from `response_json["usage"]["prompt_tokens"]`
- `output_tokens` — from `response_json["usage"]["completion_tokens"]`
- `citations` — from `response_json["citations"]`, a flat list of URL strings; titles are `None`

**Claude (Anthropic API with web search)**
- `model_version` — from `response.model`
- `response_text` — concatenation of all `text` content blocks in `response.content`
- `input_tokens` — from `response.usage.input_tokens`
- `output_tokens` — from `response.usage.output_tokens`
- `citations` — from `web_search_result` content blocks in `response.content`; each block has `url` and `title`

## 5. API Contracts

### 5.1 ChatGPT — OpenAI Responses API

**API:** OpenAI Responses API (`client.responses.create`)
**Model:** `gpt-4o` (resolved at runtime; `model_version` recorded from response)

**Request parameters:**

| Parameter | Value |
|---|---|
| `model` | `"gpt-4o"` |
| `tools` | `[{"type": "web_search_preview"}]` |
| `input` | The prompt string |
| `max_output_tokens` | `1500` |

**Output extraction:**

Iterate `response.output`. Items have a `type` field:
- `type == "web_search_call"` — `results` list, each with `url` and `title`; collect in order for citations
- `type == "message"` — `content` list; text answer is in the part where `type == "output_text"`, accessed as `.text`

If no `web_search_call` item is present, citations is an empty list. This is valid, not an error.

**Cost calculation:** `(input_tokens * 0.0000025) + (output_tokens * 0.000010)` (GPT-4o pricing as of 2026-04; update in `openai_engine.py` with a note in `decisions-log.md` if pricing changes).

---

### 5.2 Perplexity — Sonar API

**API:** Perplexity Sonar REST API (plain HTTP via `requests`)
**Model:** `sonar`
**Endpoint:** `https://api.perplexity.ai/chat/completions`

**Request parameters (JSON body):**

| Parameter | Value |
|---|---|
| `model` | `"sonar"` |
| `messages` | `[{"role": "user", "content": <prompt>}]` |
| `max_tokens` | `1500` |
| `search_recency_filter` | `"month"` |

**Headers:** `Authorization: Bearer <PERPLEXITY_API_KEY>`, `Content-Type: application/json`

**Output extraction:**
- Answer: `response_json["choices"][0]["message"]["content"]`
- Citations: `response_json["citations"]` — flat list of URL strings; position is list index + 1; titles are `None`
- Model: `response_json["model"]`
- Tokens: `response_json["usage"]["prompt_tokens"]` / `["completion_tokens"]`

**Error handling:** HTTP status != 200 raises immediately. The run is recorded with `error` set to the status code and response body. Partial data is still written to `runs`.

**Cost calculation:** `(input_tokens * 0.000001) + (output_tokens * 0.000001)` (Sonar pricing as of 2026-04).

---

### 5.3 Claude — Anthropic API with Web Search

**API:** Anthropic Messages API (`client.messages.create`)
**Model:** `claude-sonnet-4-6` (version string recorded from `response.model`)

**Request parameters:**

| Parameter | Value |
|---|---|
| `model` | `"claude-sonnet-4-6"` |
| `tools` | `[{"type": "web_search_20250305", "name": "web_search", "max_uses": 3}]` |
| `messages` | `[{"role": "user", "content": <prompt>}]` |
| `max_tokens` | `1500` |

**Output extraction:**

Iterate `response.content` blocks by `type`:
- `"text"` — append `.text` to `response_text` accumulator
- `"web_search_result"` — each block has `.url` and `.title`; collect in encounter order for citations
- Other types (e.g., `tool_use`, `tool_result`) — ignored

**Cost calculation:** `(input_tokens * 0.000003) + (output_tokens * 0.000015)` (Claude Sonnet 4.6 pricing as of 2026-04).

## 6. `prompts.yaml` Structure

Loaded by `runner.py` with `yaml.safe_load()` at the start of each pipeline run.

### Canonical Query Entry

```yaml
- id: "brand-visibility-q1"           # Unique slug; used as query_id in SQLite; lowercase, hyphens only
  topic: "Brand Visibility in AI"      # Human-readable topic label for reports
  prompt: |                            # Exact prompt sent to all three engines verbatim
    Which companies are most prominently
    featured when someone asks about [topic]?
    List the top 5 with brief reasoning.
  is_variant: false
  variant_of: null
  notes: "Core brand visibility query" # Optional; never sent to engines
```

### Stability Variant Entry

```yaml
- id: "brand-visibility-q1-v2"
  topic: "Brand Visibility in AI"
  prompt: |
    Name the five companies that appear most often in AI engine responses
    about [topic]. Explain why each is prominent.
  is_variant: true
  variant_of: "brand-visibility-q1"   # Must match the id of the canonical prompt
  notes: "Reworded for prompt stability sub-study"
```

### Constraints

- At least 5 canonical queries must each have at least one variant (prompt stability requirement)
- `id` values must be globally unique across the entire file
- No templating is performed on `prompt` text; what is in the YAML is sent verbatim
- The pipeline records `is_variant` and `variant_of` in the `queries` table; report analysis uses these columns to separate canonical from variant runs

## 7. GitHub Actions Workflow Spec

**File:** `/.github/workflows/monthly-sweep.yml`

### Trigger

```yaml
on:
  schedule:
    - cron: "0 2 1 * *"    # 02:00 UTC on the 1st of every month
  workflow_dispatch:         # Manual trigger; runs full pipeline identically to scheduled run
```

Single job on a single `ubuntu-latest` runner. Parallelism is handled within Python, not at the Actions level.

### Secrets Required

Set in repo Settings > Secrets and variables > Actions:
- `ANTHROPIC_API_KEY`
- `OPENAI_API_KEY`
- `PERPLEXITY_API_KEY`
- `NOTION_API_KEY`
- `NOTION_REVIEW_DATABASE_ID`

`MONTHLY_BUDGET_USD` is hardcoded as `40` in the workflow env block, not stored as a secret.

### Job Steps (in order)

1. **Checkout** — `actions/checkout@v4` with `fetch-depth: 0`
2. **Setup Python** — `actions/setup-python@v5` with `python-version: "3.12"`
3. **Install dependencies** — `pip install -r requirements.txt`
4. **Validate environment** — `python run.py test`. If this step fails, the job fails immediately and no API spend is incurred.
5. **Run pipeline** — `python run.py run`. Budget circuit breaker is active throughout. Exits with code 2 if circuit breaker fires (distinct from general failure code 1).
6. **Generate report** — `python run.py report`. Runs even if circuit breaker fired; generates a partial report noting the budget failure.
7. **Commit results** — `git` CLI commits `data/observatory.db` and new files in `reports/`. Commit message format: `data: monthly sweep YYYY-MM [N runs, $X.XX spent]`. The N and cost are written to `$GITHUB_ENV` by `run.py run` when `GITHUB_ACTIONS` env var is present. Git user set to `github-actions[bot]`.
8. **Push** — `git push origin main`. No force push.
9. **Post to Notion** — `python run.py report --notify`. Only runs if commit+push succeeded (`if: success()`).

### Failure Handling

Final step with `if: failure()` opens a GitHub issue:

```
gh issue create \
  --title "Monthly sweep failed: YYYY-MM" \
  --body "Workflow run: ${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}" \
  --label "pipeline-failure"
```

`gh` CLI is available on `ubuntu-latest` without installation; `GITHUB_TOKEN` is used automatically.

### Budget Circuit Breaker Behavior

Checked in `budget.py` before every API call via a single aggregate query on `costs`. If the current month's total meets or exceeds `MONTHLY_BUDGET_USD`, the call is skipped and logged to stdout. After all queries, if any were skipped, `run.py run` exits with code 2. Partial results collected before the circuit breaker fired are committed normally.

## 8. Notion Integration Spec

**File:** `/src/notifier.py`

The Notion integration is a review gate only. No data is read from Notion. If the Notion POST fails, a warning is logged but the workflow step is marked as succeeded.

### Notion Database Properties

The `NOTION_REVIEW_DATABASE_ID` database must be configured with these properties before first use. The pipeline does not create the database or its schema.

| Property Name | Notion Type | Value |
|---|---|---|
| `Month` | Title | `"YYYY-MM"` |
| `TotalRuns` | Number | Total count of rows in `runs` for this month |
| `EnginesCovered` | Multi-select | Subset of `["chatgpt", "perplexity", "claude"]` with at least one completed run |
| `UniqueCitationDomains` | Number | Count of distinct `domain` values in `citations` for this month |
| `TotalCostUSD` | Number | Sum of `cost_usd` from `costs`, rounded to 4 decimal places |
| `BudgetBreached` | Checkbox | `true` if `TotalCostUSD >= MONTHLY_BUDGET_USD` |
| `ReportURL` | URL | GitHub URL to committed report: `https://github.com/groxburgh/aeo-geo-research-lab/blob/main/reports/YYYY-MM.md` |
| `Status` | Select | `"Needs Review"` on creation; manually changed to `"Approved"` or `"Flagged"` |
| `CreatedAt` | Date | ISO-8601 UTC timestamp of Notion page creation |

### API Call

- `POST https://api.notion.com/v1/pages`
- Headers: `Authorization: Bearer <NOTION_API_KEY>`, `Notion-Version: 2022-06-28`, `Content-Type: application/json`
- On HTTP error: log at WARNING level, catch exception in caller, exit 0 regardless.

## 9. `run.py` Interface

`run.py` is the sole entry point. It uses `sys.argv` directly (not Click or argparse) — there are only three commands and one optional flag.

### `python run.py test`

Pre-flight validation. Fast and cheap. Always runs in CI before any API spend.

1. Checks all five required env vars are set; exits 1 listing missing ones
2. Validates `prompts/prompts.yaml` parses cleanly and every entry has required fields; exits 1 on schema error
3. Applies SQLite schema to `data/observatory.db`; exits 1 on failure
4. Sends a single minimal call to each engine (`"Reply with one word: ready"`); calls not recorded to SQLite; exits 1 if any engine errors

Stdout format: `[OK] Environment variables` / `[FAIL] prompts.yaml: missing field 'id' at entry 3`

Exit codes: 0 success, 1 any failure.

---

### `python run.py run`

Full monthly batch. Query iteration order: YAML file order. Engine order: `chatgpt`, `perplexity`, `claude`. Run numbers: 1, 2, 3.

1. Determines current month as `YYYY-MM` (UTC)
2. Loads all queries from `prompts/prompts.yaml`
3. Writes all queries to `queries` table with `INSERT OR IGNORE`
4. Checks budget circuit breaker for current month; exits 2 immediately if already at/over budget
5. For each (query, engine, run_number): checks circuit breaker; checks if row already exists in `runs` (idempotent); calls engine; writes `NormalizedResult` to `runs` and `citations`; writes to `costs`; logs progress
6. When running in CI (`GITHUB_ACTIONS` env var set), writes `SWEEP_RUN_COUNT` and `SWEEP_COST_USD` to `$GITHUB_ENV`

Exit codes: 0 full success, 1 unhandled exception, 2 circuit breaker triggered.

---

### `python run.py report [--notify]`

1. Determines current month (UTC)
2. Queries SQLite for all runs, citations, costs for the current month
3. Generates `/reports/YYYY-MM.md` (overwrites if exists — idempotent)
4. If `--notify` flag present, calls `notifier.py`; Notion failure does not affect exit code

**Report sections (in order):**
1. Header: month, date generated, total runs, total cost, engines covered
2. Budget summary: amount spent vs cap, whether circuit breaker fired
3. Per-engine citation frequency: top 20 domains per engine, count and % of runs cited
4. Cross-engine domain overlap: domains cited by all three / exactly two / exactly one
5. Prompt stability section: Jaccard similarity on domain sets between canonical and variant runs
6. Model versions recorded: one line per engine showing all model version strings observed
7. Raw run log: collapsed table of every run (query_id, engine, run_number, cost, citation count, error flag)

Exit codes: 0 success, 1 failure.

## Appendix B: Domain Extraction

`domain` in `citations` is eTLD+1 extracted by Python. Implementation in `models.py` uses `urllib.parse.urlparse` to get hostname, then takes the last two dot-separated segments (e.g., `www.blog.nytimes.com` → `nytimes.com`). No `tldextract` dependency is added. Country-code second-level domains (e.g., `co.uk`) are not handled correctly — this is a documented limitation in `METHODOLOGY.md`.

---

## Appendix C: Idempotency Guarantee

The pipeline is safe to re-run for the same month. `UNIQUE(query_id, engine, run_number, month)` on `runs` combined with the pre-call existence check in `runner.py` ensures a re-run after partial failure picks up where it left off. `INSERT OR IGNORE` on `queries` and UUID primary keys on `citations` and `costs` are consistent with this guarantee.
